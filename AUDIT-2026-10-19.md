## Fix first

### A01 · High · Synchronize navigation, reading content, metadata, and print output

**Confirmed:** Open `/en/projects/relay`, switch to Spanish, then choose the next project. The URL and visible app change to `/projects/local-ai-server`, but the canonical URL remains the English Relay URL and the reading/print document remains English Relay. History length does not increase because the desktop uses `history.replaceState`.

Opening RESUME.DOC from the English home desktop changes the address to `/cv?lang=en`, but the print representation still contains the home document, with no CV background or skills. Even the direct CV reading representation omits sections present in WordPad.

**Impact:** Visitors can print the wrong document, read stale content, and lose expected browser Back behavior. Client-side metadata and structured content can describe a different project from the address bar.

**Improve:** Establish a shared route/content state for the desktop, reading view, metadata, and print representation. Give meaningful project/language navigation real history entries and support Back/Forward. Do not treat merely raising or minimizing a window as equivalent to navigating to a new document. Print a complete representation of the current CV/project.

**Acceptance:** Project → language → next project → reading view → print all describe the same item; Back restores the previous project; printing CV includes experience, skills, languages, and correct email.

### A02 · High · Repair Welcome on short mobile screens

**Confirmed at 320 × 568:** `.welcome-main` has 160px available but 223px of content. The tip is 105px tall while its text extends beyond it, overlapping the action buttons. The footer and floating reading shortcut crowd the bottom of the window.

At 390 × 844 the content is readable, but a large empty grey area separates the actions from the bottom preference checkbox.

**Improve:** Let the tip and button group size naturally inside one scrolling body. Keep the main actions together and avoid nested fixed heights. Use the same classic borders, palette, icons, and pixel font. Recheck short landscape screens and increased text size.

### A03 · High · Make window focus follow the visitor

**Confirmed:** Focus Control Panel on the desktop and press Enter. The window opens, but keyboard focus stays on its desktop icon. Tab then moves to the next desktop icon instead of the new app.

The window manager has no general focus-on-open or return-focus-on-close behavior. Messages/shutdown and full-screen overlays also need an explicit policy so hidden or covered controls do not remain the effective keyboard interface.

**Improve:** Focus an appropriate control or window heading when opening/restoring an app, and return focus to its launcher when closing. Keep regular desktop windows nonmodal; use modal semantics and focus containment only for dialogs that actually block interaction. On mobile, prevent tabbing through fully covered background windows. Give the reading view a real desktop return target and predictable focus restoration.

**Relevant code:** [window-frame.tsx](C:/Users/amine/Documents/archive95-portfolio-development/components/os/window-frame.tsx), [desktop.tsx:130](C:/Users/amine/Documents/archive95-portfolio-development/components/os/desktop.tsx:130).

### A04 · High · Reduce dependency exposure before deployment

**Confirmed:** `pnpm audit --prod` reports 59 advisories. Of these, 54 have dependency paths exclusively through `shadcn`, which is installed as a production dependency. The critical advisory is in `proxy-addr` under the CLI's MCP/Express dependency chain. The remaining five advisories involve build/transformation dependency paths shared with Next.

## Next polish pass

### A05 · Medium · Improve the time to useful content

In the throttled trace, the welcome SVG request began around 3,371ms and LCP occurred at 4,208ms. Most of the LCP time was waiting before the image request, not transferring the small SVG. The desktop initially renders with no open windows; welcome content is mounted after client initialization. A first-session BIOS/splash also adds a scripted delay of approximately 3.7 seconds unless skipped.

Make the personal introduction available earlier, prioritize its artwork where appropriate, and load optional apps only when needed. All active apps are currently imported eagerly by the desktop. Preserve the boot sequence as an optional nostalgic interaction rather than letting it delay the main portfolio journey. Recheck cold first visit and returning visit separately.

The trace also flagged font display as a potential contributor to text delay. Review how the 98.css font faces load before changing the established font.

### A06 · Medium · Finish accessibility semantics

- The focusable resize grip uses `role="separator"` without the required `aria-valuenow`. Choose semantics that accurately describe resizing in two dimensions, including useful instructions/state.
- About and Display put `role="tab"` on a list item wrapping a button. There are no tab/panel associations or arrow-key tab switching. ArrowRight on About's General control did not change the selected tab.
- Minesweeper declares a grid with direct gridcell children, no row structure, 81 sequential tab stops, and no directional cell navigation. Add a coherent keyboard pattern and row/column context, or use simpler honest semantics.
- Accessible names should contain the visible labels. Lighthouse flags “Back” versus “Previous”, EN/ES versus a language-switch label, and Relay node labels that omit visible step/branch text.
- Localize window-control accessible labels and other English-only accessibility strings in the Spanish interface.

These changes can retain all existing visual styling.

### A07 · Medium · Enlarge hit areas and remove remaining low contrast

Lighthouse measured tray targets around 19 × 18px and 22 × 18px. Desktop title controls are also small. Keep the visible Win95 glyphs, but provide larger invisible hit areas and more spacing, especially for touch input. A 24px minimum is a useful baseline; primary touch actions should be more comfortable than that.

The project view helper text has about 4.09:1 contrast, below the 4.5:1 threshold for its small size. Darken that text. Relay branch captions and several technical labels are still around 9–11px. Improve these selectively while retaining compact chrome.

### A08 · Medium · Preserve demo state while reading

**Confirmed:** Stop the lab gateway: health becomes 503. Switch to the dossier and return to the demo: health is 200 again. The demo component unmounts when the view changes, resetting service state, NAS changes, Relay positions/progress, and AI playback.

Keep the state above the view switch or preserve the mounted demo while suspended. Reading about a running example should not silently reset it. An explicit Reset can continue to reset the example.

**Relevant code:** [project.tsx:90](C:/Users/amine/Documents/archive95-portfolio-development/components/os/apps/project.tsx:90).

### A09 · Medium · Protect visitor drafts

**Confirmed:** Type into Notepad, close it with X, and reopen it: the edit is gone. Mail drafts are also component-local and can be replaced by opening the singleton mail app for a different project.

Use a simple dirty-state close warning or session draft preservation. Keep the Download action explicit; do not imply a note was saved merely because it exists in the app. This is especially valuable for contact messages.

### A10 · Medium · Complete language consistency

- The reading view's language link takes a project reader to the other-language homepage instead of the corresponding project.
- `/en` initially serves `<html lang="es">`; hydration corrects it, but without JavaScript the document root remains Spanish. Inner content has its own language attributes, which partly mitigates this.
- Lab statuses/logs, Relay sample payloads and story labels, NAS folder names, and some system controls remain English in Spanish mode.
- Open form defaults and README content are initialized once, so changing language does not consistently update their existing text. Preserve typed content while distinguishing it from translatable UI defaults.

### A11 · Medium · Make the CV consistent across formats

The downloadable PDF is readable, fits one page, and contains the correct email. It is English-only, although Spanish controls simply say “Download PDF” without identifying the language. Its email and GitHub strings have no PDF link annotations. Its generator duplicates content separately from the website.

Label the download language, make contact/repository links clickable, and generate shared facts from a common source. Keep the CV focused on hiring: replace internal validation-process wording with a concise factual description of personal contribution and project status. Correct school-name typography without losing accents. A Spanish export would be useful for the intended local audience, once the copy is reviewed.

### A12 · Medium · Put proof and personal contribution closer to the demo

Relay has useful workflow, architecture, and validation links. The other three labs still lack their own supplied repository/configuration evidence. Cyberdeck and CloudLink are accurately labeled related work, but they do not prove the separate lab configurations.

For each project, prioritize a short explanation of what you personally configured/built, one concrete problem solved, and one actual artifact. Keep one clear simulation label and a concise scope note; repeated internal audit language makes the portfolio harder to read. Add the separate lab evidence when you supply it. Do not invent screenshots, metrics, uptime, or outcomes.

### A13 · Medium · Respect reduced motion throughout the desktop

The demos reduce decorative motion, but the canvas screensaver still runs a continuous requestAnimationFrame starfield and starts automatically after two idle minutes. It does not check reduced-motion preferences or document visibility.

Use a static or disabled screensaver for reduced motion, suspend drawing in hidden tabs, and provide a way to avoid the automatic takeover. Check keyboard focus and announcements when the screensaver exits. Keep the nostalgic effect available to visitors who want it.

### A14 · Medium · Give mobile reading priority within existing layouts

The four project views fit the tested widths. Relay still uses much of the first screen for toolbar, controls, scenario selector, instructions, and the upper part of its map. The result/proof sits further down. Its node drag handles also use `touch-action: none`.

Reduce repeated vertical chrome on small screens, shorten instructions, and keep the purpose/result easy to find. Preserve touch scrolling around draggable nodes and the existing keyboard alternative. Reposition the fixed reading shortcut so it does not cover content or form controls. No additional app or demo is needed.

## Maintenance and release work

### A15 · Medium · Add regression coverage for the actual visitor journeys

The current automated test covers the playback reducer. There is no repository CI workflow, lint script, or committed browser smoke suite. The HTTP verifier proves route availability and expected HTML strings, but it does not test focus, print contents, browser history, demo persistence, mobile overlap, or all referenced asset failures.

Add a small, meaningful browser suite around A01–A03 and A08, plus contact links, CV download, and key demo interactions. Run build/typecheck/reducer tests and dependency checks in CI. Make the verifier fail on referenced JS/CSS/font errors rather than only printing size estimates.

### A16 · Medium · Complete the deployment handoff on the real host

The app builds and runs as a Node server locally. That is not proof that the Oracle deployment works. Verify the final domain, TLS, reverse proxy, service restart after reboot, logs, and deployment rollback on that VM. Build native dependencies on the target architecture, particularly if the instance is ARM.

Add a reviewed deployment recipe or service/container configuration appropriate to the actual host. Document the Node version and build-time origin setting. The existing security headers are useful; consider a tested CSP/frame-embedding policy as later hardening rather than adding an untested blanket policy.

### A17 · Low · Simplify styling and unused project history

`globals.css` contains several successive overrides for Welcome, title controls, demo nodes, mobile behavior, and print. The later typography rules contribute to the short-screen collision. Consolidate each component's final rules after the visual fixes, using a small shared set of spacing/type values.

Historical editorial components, placeholder images, unused tooling packages, and older asset generation remain alongside the active desktop. Remove only after checking references and retaining history in Git. Removing an unused dependency improves maintenance/install size; it does not automatically imply a smaller browser bundle.

### A18 · Low · Make build output and documentation reproducible

Every build rewrites PDF timestamps, producing a binary diff even with unchanged content. Set intentional metadata or separate release artifact generation. Rename the generic `my-project` package and document the supported runtime. Update the verification document so obsolete missing-origin statements are clearly historical; the proposed production origin is now configured. Resolve the vendor CSS warning through a controlled dependency correction rather than stacking unrelated overrides.

## Recommended order

1. **Correctness:** A01 navigation/printing, A02 short-screen Welcome, A03 focus, and A04 dependency cleanup. Add regression checks for these fixes.
2. **Usability:** A06–A10 semantics, hit areas, demo persistence, drafts, and language consistency. Apply A13 reduced motion and A14 mobile hierarchy while keeping the current aesthetic.
3. **Presentation and release:** A05 performance, A11 CV consistency, A12 real evidence, then CI/deployment and source cleanup.

A successful polish pass should let a visitor understand who you are, inspect one convincing project, read/download the CV, and contact you comfortably on mouse, keyboard, or phone. More features can wait until those paths are dependable.
